# プロジェクト管理・アーティファクト構成方針

## 1. ライブラリ・環境管理
環境の再現性と柔軟性を両立するため、Docker と uv を併用して管理します。

* **基本環境**: Docker を使用して構築。
* **操作インターフェース**: `Makefile` および `Dockerfile` を参照。
* **自動セットアップ**: ビルド時に `requirements.txt` に記載されたライブラリを自動でインストール。
* **動的追加**: 開発中に必要になったライブラリは `uv` を使用して管理・追加する。

---

## 2. アーティファクト管理 (artifacts/)
実験結果は、後からの追跡やアンサンブル、ログ確認を容易にするため、以下のディレクトリ構造で保存します。
※ 状況に応じて、より適切な構成へ柔軟に変更・拡張を行います。

artifacts/
└── experiments/
    └── exp001_baseline/          # 実験名（手法・モデルの概要）
        └── 000/                   # トライアルID（実行番号）
            ├── fold0/             # 各Foldの学習済みモデル
            │   └── model_best.ckpt
            ├── fold1/
            │   └── model_best.ckpt
            ├── ...
            ├── fold4/
            │   └── model_best.ckpt
            │
            ├── wandb/             # W&B ログ（offline / cache / sync 用）
            │   └── run-xxxx/
            │
            ├── log/               # 実行ログ
            │   └── train_exp001_000_20250121-193045.log
            │
            ├── OOF/               # Out-of-Fold 予測結果（CSV形式等）
            │   └── OOF_exp001_000_20250121-193045.csv
            │
            ├── submission/        # 提出用予測ファイル
            │   └── SUB_exp001_000_20250121-193045.csv
            │
            └── meta.yaml          # 実験のメタ情報（ハイパラ・設定等）

---

## 3. 運用ルール
* **一意性**: ログ、OOF、submission ファイル名には `実験ID_トライアルID_タイムスタンプ` を付与する。
* **再現性**: `meta.yaml` を活用し、どのような設定で実行された結果かを常に紐付け可能にする。
